# 代码标准

本文件的规则来自评审与返工里反复出现的要求。评审人对照每一条检查 PR；
提交人在提交前对照过一遍。

哪些文档属于"评审与修改的语境"，见 [AGENTS.md](../AGENTS.md)。

---

## 一次提交长什么样

| 规则 | 评审人看什么 |
| --- | --- |
| 一次提交只做它声明的那件事。 | 每一处行为变化都有理由。无关的重构、夹带的特性、策略修改单独提交。 |
| 修复只覆盖它打算覆盖的 case，不多不少。 | 哪一类 case 被改了，哪一类相邻的保持不变。不同的错误不并成一筐处理。 |
| 修复覆盖整条路径。 | 从用户输入追到最终结果，经调用方、被改的状态、副作用。改对一个函数不等于改对这整条路径。 |
| 修复覆盖这个 bug 的所有"兄弟位置"。 | grep 一遍同形的模式：其它部件、其它分支、其它入口。同形状的错要么一起修，要么显式说明为什么不修。 |
| 改动会推导出所有建立在它之上的东西。 | 改了公式 / 常量 / 列表 / 布局断点 / 异步时序时，找出每个假设旧值的 caller、已保存的副本、测试，并把它们一起跑过。 |
| 检查覆盖这个改动触到的边界。 | 数值边界；桌面端 / brain 两侧；并发场景下的 stale 状态。按风险选检查项。 |

## 验证

> 当前项目的验证手段 = typecheck + lint + build + `scripts/e2e-*.mjs` 专项脚本
> + 手动自测。新加的验证手段（单测 / 集成测试 / CI）成熟后更新本节，
> 原则是"加了新行为就要有新验证"。

| 规则 | 评审人看什么 |
| --- | --- |
| 每个 fix / feat 都配一个"缺了它就会挂"的验证。 | 写完验证后，把修复撤掉 → 验证必须失败；恢复修复 → 验证必须过。body 里写清失败时的输出。编译错、被跳过的测试不算。 |
| 验证用真实输入。 | fixture 用真实请求体 / 真实配置 / 真实日志。缺字段、空值、默认值都要覆盖。 |
| 验证断言的是行为，不是实现细节。 | 断言用户或调用方能感知的结果。重命名了内部函数不该让测试挂，除非字节级一致是需求。 |
| 验证脚本退出后不留尾巴。 | 它启动的进程、监听、定时器在脚本返回前全部清理。 |
| 时序断言两侧都留余量。 | 复现时间类 bug 用注入延迟（人为卡住某个步骤），不是靠 `-count=N` 撞运气。 |
| 不自欺：跑了什么就写什么。 | body 里明确列出跑过的命令和没跑的项目。"没跑"不是失误，是事实；藏着不报才是问题。 |

### 序列嵌套 bug 的专门规则

触发条件是"连续操作叠加状态 / 时机"的 bug——打断中又来一轮、滚动后
点击、播放中切换、反复开合后错位之类——**不接受"手动自测"作为唯一验证**。
手点过一次没复现，什么都证明不了；下次任何人改到相邻代码，bug 就回来了。

修复必须带一个 `scripts/e2e-*.mjs` 序列回放：

- 脚本逐字回放触发操作序列（先做什么、再做什么），每一步断言
  **该发生的和不该发生的**（旧状态不残留、页面不跳动、口型不归零地挂着）。
- 每一步的触发用**条件等待**：store watcher / `waitFor` 轮询状态成立，
  禁止用固定 `sleep(N)` 去撞时序窗口（参考 `e2e-chat-stop.mjs` 的
  页面内订阅写法）。
- 修复前先在未修复的代码上跑红，body 里记录红的输出。
- 脚本头部注释写明：复现的操作序列、对应的 issue / 报告来源。

新脚本放 `scripts/` 即自动被 `npm run e2e` 收编进回归套件，无需登记。

## 验收清单（提交或合并前必须满足）

提交 body 里逐条列出跑了哪几项、结果是什么。**没跑的项要写成 "not run"，
绝不能省略**。

1. **修复撤掉后验证会红。** 按上面"验证"一节的方式自证。
2. **`npm run typecheck` 过。** `tsc --noEmit` 会查 `_test`/未编译路径，
   IDE 里看到的红线不算数。
3. **`npm run lint` 过。**
4. **`npm run build` 过**（涉及 desktop 改动时）。打包层面的错（依赖打包、
   资源引用）只有 electron-vite 完整 build 能暴露。
5. **相关的 e2e 脚本过。** 用户可见的行为变化对应地跑 `scripts/e2e-*.mjs`
   （哪个相关清单见 AGENTS.md），或写一个新的 e2e 放进这次提交。
   改动了共享状态、时序或 IPC 边界的，跑 `npm run e2e` 全量回归。
   **序列嵌套 bug 见上一节：手动自测不算数。**
6. **真实环境验证过。** 涉及 LLM / STT / TTS / Live2D 参数 / 持久化的改动，
   在真实桌面端跑一遍真实对话，不是只看 typecheck。没法真验的写明
   "not tried against the real …"。

## 文档与提交同步

- 行为变化在同一提交里同步文档：`docs/v1-requirements.md`（范围变化时）、
  `AGENTS.md`（命令或流程变化时）、本文件（规则变化时）。
- 新增子系统设计文档放 `docs/`，写清：职责、真实源头文件、关键状态、
  主要运行时路径、不能违反的约束、怎么验证（可复制的命令）。
- 文档不抄实现细节（函数名、行号会过期），链接到源文件里的命名符号。

## 用户数据的安全（针对 Electron 桌面端的落点）

> 这一节来自同类 agent 项目反复出事故的教训。本项目的对应位置：
> 脑服务的会话库（pg）、`services/brain/skills/.amadeus-state.json`、
> Electron 端的 userData 目录、用户的 LLM key。

- **读取 / 解析失败 = "未知"，不等于 "空"。** 状态文件解析失败时：
  绝不写入、保留现场、读上次的 `.bak`，并让用户知道。
- **删除前找出所有可能匹配同一 key 的记录。** 不用显示名匹配账号 / 会话。
- **不要主动覆盖用户改过的内容。** 同步 / 自动写回策略要测
  "用户手改了 → 再触发一次同步"的场景。
- **写入类操作要走"先备份、再覆盖"两步**，且失败时不落盘半截。

## 恶意输入与隐私

- 用户输入（提示词、文件路径、shell 片段）不能不经处理进 shell、SQL、
  HTML（本项目桌面端 React 侧已是 `rehype-sanitize` 处理，扩展到新入口时
  沿用这一约束，不引入"绕过 sanitize 的便捷通道"）。
- 发给模型或第三方的内容做最小化：只发完成这次请求所必需的字段。
  新增要发给外部的字段 / 遥测时，同 commit 里在 README 的隐私说明里
  如实更新。
