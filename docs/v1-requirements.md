# pi-amadeus v1 需求文档

> 状态：v1 范围已确认（2026-08-16 讨论）。本文档定义"做什么"；技术选型细节在后续设计文档展开。
> 依据：工作区 CLAUDE.md 的重构目标清单 + 本次讨论确认的取舍。

## 1. 项目定位

基于 pi 基座重构的 Amadeus：命运石之门 0 风格 AI 陪伴助手（Kurisu 傲娇人格），桌面形态 + 实时语音对话 + Live2D 虚拟形象，多渠道（桌面 / 飞书）。v1 的首要交付物是**界面**（聊天 UI + Live2D 场景）。

## 3. 架构约束

- **基座**：LLM 接入统一走 pi-ai（多供应商、流式），对话编排基于 pi 能力。pi 只做基座，一般不改。
- **参考原则**：amadeus-system-new 只作为功能规格参考（功能点、数据流、跨端契约），实现全部重写。**使用相同的开源库（fastrtc、pixi-live2d-display 等）允许；照搬其业务代码与架构禁止。**
- **语言**：TS（前端 + 对话大脑服务）+ Python（仅媒体桥）。
- **存储**：SQLite 单文件（Node 内置 `node:sqlite`，默认 `services/brain/data/amadeus.db`，可用 `DB_PATH` 覆盖）。不需要安装数据库服务；不使用 pi coding-agent 的 JSONL `SessionManager`；pi-amadeus 自建 schema，对话编排层保持内存态、由服务层持久化。

## 4. 总体拓扑（建议）

```
┌─ Electron 壳 + 前端（React + TS，Vite）──────────────┐
│  · 壳：窗口 / 托盘 / 更新 / fork 大脑服务进程          │
│  · 文本聊天 UI（SSE 消费、Markdown、会话列表/历史）    │
│  · Live2D 场景（pixi-live2d-display，表情/口型/动作） │
│  · WebRTC 客户端（麦克风 / 扬声器 / 摄像头）           │
└───────────────┬─────────────────────────────────────┘
                │ HTTP + SSE / WebRTC
┌───────────────▼─────────────────────────────────────┐
│ 对话大脑服务（Node/TS，pi 基座）                      │
│  · pi-ai 多供应商 LLM + 流式                          │
│  · 人格 prompt 构建 + 双语言输出解析                   │
│  · 会话编排 + SQLite 持久化                           │
│  · 飞书机器人（与桌面共享同一对话服务）                 │
│  · TTS 调用（Audio Fish）                            │
└───────────────┬─────────────────────────────────────┘
                │ HTTP（文本 / 音频）
┌───────────────▼─────────────────────────────────────┐
│ 媒体桥服务（Python）                                  │
│  · WebRTC（fastrtc）+ 人声感知 VAD                    │
│  · STT（Whisper）                                    │
│  · TTS 音频回注 WebRTC 流                             │
└───────────────┬─────────────────────────────────────┘
                │
      SQLite 文件（data/amadeus.db）
```

职责划分原则（相对原版的改进）：**Python 只负责媒体进出，一切 AI 决策与对话逻辑都在 TS 大脑**——与 pi 基座同栈、单点演进。原版 Python 用 langchain 当大脑，v1 由 pi-ai 取代。

（备选：若 Audio Fish / Whisper 接口允许，STT/TTS 也可由 TS 直接调 HTTP API，Python 仅剩 WebRTC 传输。实现时按接口形态定。）

## 5. 功能需求

### 5.1 人格系统 + 中日双语言输出（核心）

- 可配置系统提示词：Kurisu 傲娇人格模板，支持用户自定义覆盖（按用户存储）。
- **会话模式共享（重要）**：语音与文本窗口共用**同一个会话模型与消息序列**，一个会话可以随时在两种窗口间切换继续（修正原版"文本会话 / 语音会话两套互不相通"的缺陷）。**"模式"是回合级属性，不是会话级属性**——每个回合按发起时的模式决定输出格式，历史消息对两种模式都只是普通中文上下文。
- **回合级输出格式**：
  - **语音回合**：LLM 流式输出中日双语，两段内容语义完全一致，用 prompt 约定的标识符区分。日文段 → TTS 合成语音播放；中文段 → UI 显示。
  - **文本回合**：LLM 只输出中文（prompt 更简单、token 更省），不调用任何语音能力。
- **中文是规范内容（canonical）**：SSE `delta` 与 UI 展示永远只有中文。**日文随消息以隐藏字段一并落库**（不展示、不进 LLM 上下文——上下文只拼中文，避免 token 翻倍），为后续版本的历史语音回放留数据。回放时用存储的 `tts_text` 重新合成即可，无需存音频文件（Audio Fish 音色固定，重合成结果一致）。双语言标记格式是**大脑 ↔ LLM 的内部契约**，前端展示层无感知（回放功能启用时再暴露）。
- 流式格式要求：**日文先于中文产出**（TTS 是延迟敏感路径），并按句子粒度分段对齐（TTS 按标点切句）。
- 容错：LLM 未按约定输出标识符时需降级策略（缺日文 → 跳过 TTS，全文按中文显示；格式错误 → 容错解析）。
- 模型：需日文能力强的模型；pi-ai 内置 provider 均可配置。
- 情绪输出（供 Live2D）：优先与 LLM 流**内联**（流中带情绪标记，省一次额外 LLM 调用）；如效果差再退独立轻量分类调用。实现时定。情绪标记同样属于内部契约，不落库。

### 5.2 文本聊天

- SSE 流式响应，事件词汇沿用：`delta` / `done` / `error`（`conflicts` 随长期记忆一并移除）。
- 会话：新建（延迟到首条消息）、列表（按天分组：今天 / 昨天 / 本周 / 更早）、删除、按 channel 区分（desktop / feishu）。
- 会话自动标题：首轮问答后异步生成。
- 消息 Markdown 渲染（react-markdown + rehype-sanitize）。
- 流式中断（AbortController）。

### 5.3 实时语音对话

- WebRTC 接入：fastrtc，人声感知 VAD（区分人声 / 背景音，非纯能量检测）。
- STT：接口**占位符**（具体内容已编写，待提供后接入）。
- 对话回路：VAD 停顿 → STT 转写 → （视觉帧附加）→ LLM 双语言流 → 日文切句 → Audio Fish TTS → 有序音频队列播放；中文实时上屏。
- 打断：用户重新说话可打断当前 TTS 队列。
- **主动发言：v1 不做**。取而代之：Live2D 页面提供**开发者调试按钮 + 文本输入框**——直接输入中文文本即可走完整语音回合链路（双语言流 → 日文 TTS 播放、中文上屏），无需麦克风，用于开发期验证语音链路。

### 5.4 Live2D 虚拟形象

- Cubism 3 模型，沿用红莉栖 Kurisu 模型资产（属资源非代码，可整体迁移）。资产位置：`amadeus-system-new/public/live2dmodels/`。
- **形象可切换**（配置面板「形象」页）：默认红莉栖；另收录 Live2D 官方示例模型 Mao Pro / Shizuku（移植自 Open-LLM-VTuber 的 `live2d-models/`），用于调试模型加载、口型与动作。模型切换会重建 Live2D 舞台；摆位（缩放/位移）按模型分别保存。非红莉栖模型没有专属情绪脸与漫画符号，程序层通过参数映射驱动眨眼/口型/姿态。
- Cubism Core 随模型升级到 5.0（`public/live2d/live2dcubismcore.min.js`），以支持 Mao Pro 的 moc3 v5；旧版 moc3（含红莉栖 v4）保持兼容。
- LLM 情绪分类 → 表情枚举 ↔ `.exp3.json` 一一映射，驱动表情与 motion 动作。
- 音频驱动口型同步（TTS 音频幅度 → 口型参数）。
- 待机程序化动画（眨眼、头部微动等）。

### 5.5 飞书渠道

- 与桌面聊天**共享同一对话服务与数据库**，会话标记 `channel=feishu`（修正原版两套互不相通的问题）。
- @提及触发回复；绑定码绑定用户身份；回复走文本模式中文。
- 飞书侧无语音 / Live2D。

### 5.6 视觉输入

- 摄像头开启后前端采集帧（base64 JPEG），服务端每用户保留最近 2 帧。
- 语音对话时作为 image content 块附加到 LLM 请求（pi-ai Message 原生支持 image content）。
- 文本聊天模式不附加。

### 5.7 SQLite 存储

- 单文件数据库，默认 `services/brain/data/amadeus.db`（`DB_PATH` 可覆盖）；brain 启动时自动建库建表，无需安装数据库服务。
- 表：`sessions`（id / user / channel / title / 时间）、`messages`（role / content / `tts_text`（语音回合日文，可空）/ 时间）、`users`（渠道用户绑定，飞书）、`user_configs`（用户级配置，JSON 文本）。
- **配置单一来源**：以服务端 SQLite 为准（修正原版 localStorage / 数据库 / 进程内 dict 三处重复存储的问题）。
- v1 无向量检索（Milvus / etcd / MinIO 全部不需要）。

### 5.8 声音（Audio Fish）

- TTS 使用 Audio Fish 预置声音（内含配置好的音色），不做声音克隆。
- v1 先实现为**占位符接口**（返回 mock 音频，保证链路可跑通）；具体接入内容已由需求方编写，待提供后替换落地。

### 5.9 桌宠模式

- 角色以透明、置顶、铺满当前显示器工作区的独立窗口浮在桌面上；进入时主窗口隐藏，退出时恢复。
- 入口：陪伴模式舞台底栏按钮、托盘菜单；托盘提供窗口模式 / 桌宠模式切换与显示 / 隐藏 / 退出。
- 桌宠窗口内也能回到窗口模式：角色右键菜单、对话框底栏按钮。
- 角色可拖动换位置、滚轮缩放；位置与大小记在 `pet_config`，下次进入恢复。
- 待机与戳一戳都是「动作 × 表情」的组合，不是只有动作；害羞只在戳一戳时出现。
- 交互逻辑参考 XnneHangLab 的桌宠模式。行为、时序与验证见 [pet-mode.md](pet-mode.md)。

## 6. 跨端契约（从原版保留）

- SSE 事件词汇：`delta` / `done` / `error`（`delta` 内容永远只有中文）；语音模式另需 `transcript` / `emotion_response` 等（细节实现时定）。
- 用户配置模型（原 `InputData`）：LLM 端点 / 密钥 / 模型、输出语言、system prompt 等 → 迁移为**共享类型包**（修正原版无共享类型的问题）。
- 双语言流式标识符约定：v1 新增，**仅大脑服务内部**（LLM 流解析 + TTS 切句）使用，前端与存储无感知。

## 7. 明确不做（v1）

- 长期记忆（记忆提取 / RAG / 冲突澄清 / 会话摘要压缩）→ 后续版本
- 声音克隆 → 后续版本（Audio Fish 替代）
- 测试 → 核心链路稳定后补
- Milvus / etcd / MinIO 等向量基础设施
