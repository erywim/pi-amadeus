# pi-amadeus v1 需求文档

> 状态：v1 范围已确认（2026-08-16 讨论）。本文档定义"做什么"；技术选型细节在后续设计文档展开。
> 依据：工作区 CLAUDE.md 的重构目标清单 + 本次讨论确认的取舍。

## 1. 项目定位

基于 pi 基座重构的 Amadeus：命运石之门 0 风格 AI 陪伴助手（Kurisu 傲娇人格），桌面形态 + 实时语音对话 + Live2D 虚拟形象，多渠道（桌面 / 飞书）。v1 的首要交付物是**界面**（聊天 UI + Live2D 场景）。

## 3. 架构约束

- **基座**：LLM 接入统一走 pi-ai（多供应商、流式），对话编排基于 pi 能力。pi 只做基座，一般不改。
- **参考原则**：amadeus-system-new 只作为功能规格参考（功能点、数据流、跨端契约），实现全部重写。**使用相同的开源库（fastrtc、pixi-live2d-display 等）允许；照搬其业务代码与架构禁止。**
- **语言**：TS（前端 + 对话大脑服务）+ Python（仅媒体桥）。
- **存储**：SQLite 单文件（Node 内置 `node:sqlite`，默认 `services/brain/data/amadeus.db`，可用 `DB_PATH` 覆盖）。不需要安装数据库服务；不使用 pi coding-agent 的 JSONL `SessionManager`；pi-amadeus 自建 schema，对话编排层保持内存态、由服务层持久化。

│  · 壳：窗口 / 托盘 / 更新 / fork 大脑服务进程          │
│  · 文本聊天 UI（SSE 消费、Markdown、会话列表/历史）    │
│  · Live2D 场景（pixi-live2d-display，表情/口型/动作） │
│  · WebRTC 客户端（麦克风 / 扬声器 / 摄像头）           │
└───────────────┬─────────────────────────────────────┘
                │ HTTP + SSE / WebRTC
┌───────────────▼─────────────────────────────────────┐
│ 对话大脑服务（Node/TS，pi 基座）                      │
│  · pi-ai 多供应商 LLM + 流式                          │
│  · 人格 prompt 构建 + 双语言输出解析                   │
│  · 会话编排 + SQLite 持久化                           │
│  · 飞书机器人（与桌面共享同一对话服务）                 │
│  · TTS 调用（Audio Fish）                            │
└───────────────┬─────────────────────────────────────┘
                │ HTTP（文本 / 音频）
┌───────────────▼─────────────────────────────────────┐
│ 媒体桥服务（Python）                                  │
│  · WebRTC（fastrtc）+ 人声感知 VAD                    │
│  · STT（Whisper）                                    │
│  · TTS 音频回注 WebRTC 流                             │
└───────────────┬─────────────────────────────────────┘

职责划分原则（相对原版的改进）：**Python 只负责媒体进出，一切 AI 决策与对话逻辑都在 TS 大脑**——与 pi 基座同栈、单点演进。原版 Python 用 langchain 当大脑，v1 由 pi-ai 取代。

（备选：若 Audio Fish / Whisper 接口允许，STT/TTS 也可由 TS 直接调 HTTP API，Python 仅剩 WebRTC 传输。实现时按接口形态定。）

## 5. 功能需求

### 5.1 人格系统 + 中日双语言输出（核心）

- 可配置系统提示词：Kurisu 傲娇人格模板，支持用户自定义覆盖（按用户存储）。
- **会话模式共享（重要）**：语音与文本窗口共用**同一个会话模型与消息序列**，一个会话可以随时在两种窗口间切换继续（修正原版"文本会话 / 语音会话两套互不相通"的缺陷）。**"模式"是回合级属性，不是会话级属性**——每个回合按发起时的模式决定输出格式，历史消息对两种模式都只是普通中文上下文。
- **回合级输出格式**：
  - **语音回合**：LLM 流式输出中日双语，两段内容语义完全一致，用 prompt 约定的标识符区分。日文段 → TTS 合成语音播放；中文段 → UI 显示。
  - **文本回合**：LLM 只输出中文（prompt 更简单、token 更省），不调用任何语音能力。
- **中文是规范内容（canonical）**：SSE `delta` 与 UI 展示永远只有中文。**日文随消息以隐藏字段一并落库**（不展示、不进 LLM 上下文——上下文只拼中文，避免 token 翻倍），为后续版本的历史语音回放留数据。回放时用存储的 `tts_text` 重新合成即可，无需存音频文件（Audio Fish 音色固定，重合成结果一致）。双语言标记格式是**大脑 ↔ LLM 的内部契约**，前端展示层无感知（回放功能启用时再暴露）。
- 流式格式要求：**日文先于中文产出**（TTS 是延迟敏感路径），并按句子粒度分段对齐（TTS 按标点切句）。
- 容错：LLM 未按约定输出标识符时需降级策略（缺日文 → 跳过 TTS，全文按中文显示；格式错误 → 容错解析）。
- 模型：需日文能力强的模型；pi-ai 内置 provider 均可配置。
- 情绪输出（供 Live2D）：优先与 LLM 流**内联**（流中带情绪标记，省一次额外 LLM 调用）；如效果差再退独立轻量分类调用。实现时定。情绪标记同样属于内部契约，不落库。

### 5.2 文本聊天

- SSE 流式响应，事件词汇沿用：`delta` / `done` / `error`（`conflicts` 随长期记忆一并移除）。
- 会话：新建（延迟到首条消息）、列表（按天分组：今天 / 昨天 / 本周 / 更早）、删除、按 channel 区分（desktop / feishu）。
- 会话重命名与搜索：标题栏内联重命名（Enter / 失焦提交、Esc 取消），重命名不刷新 `updated_at`；侧栏按标题搜索（`⌘/Ctrl+K` 聚焦、Esc 清空）。尚未落库的空会话由服务端在重命名时按当前身份补建。
- 会话自动标题：首轮问答后异步生成。
- 消息 Markdown 渲染（react-markdown + rehype-sanitize）；代码块带语言标签与一键复制。
- 消息操作：复制用户 / 助手消息；对最后一条助手回复可「重新生成」——活动路径切换到同一用户消息下的新回复，旧回复作为兄弟节点保留，可从世界线切回；失败保留旧分支，且不重复写入用户消息。
- 回合失败可见：错误信息与重试入口以错误卡留在会话里；发起新回合时清除。
- 滚动跟随：用户上滚后暂停自动跟随并显示「回到底部」；自己发送消息时强制跟到底部。
- 快捷键：`⌘/Ctrl+N` 新建会话，`Esc` 停止生成。
- 流式中断（AbortController）。
- 文本聊天之外的附件/图片输入、消息编辑/分支与 token 用量作为 v1 扩展已实现，详见 5.17、5.21 与 [attachments-branches.md](attachments-branches.md)。

### 5.3 实时语音对话

- WebRTC 接入：fastrtc，人声感知 VAD（区分人声 / 背景音，非纯能量检测）。
- STT：接口**占位符**（具体内容已编写，待提供后接入）。
- 对话回路：VAD 停顿 → STT 转写 → （视觉帧附加）→ LLM 双语言流 → 日文切句 → Audio Fish TTS → 有序音频队列播放；中文实时上屏。
- 打断：用户重新说话可打断当前 TTS 队列。
- **主动发言：v1 不做**。取而代之：Live2D 页面提供**开发者调试按钮 + 文本输入框**——直接输入中文文本即可走完整语音回合链路（双语言流 → 日文 TTS 播放、中文上屏），无需麦克风，用于开发期验证语音链路。

### 5.4 Live2D 虚拟形象

- Cubism 3 模型，沿用红莉栖 Kurisu 模型资产（属资源非代码，可整体迁移）。资产位置：`amadeus-system-new/public/live2dmodels/`。
- **形象可切换**（配置面板「形象」页）：默认红莉栖；另收录 Live2D 官方示例模型 Mao Pro / Shizuku（来自 Live2D 官方示例模型），用于调试模型加载、口型与动作。模型切换会重建 Live2D 舞台；摆位（缩放/位移）按模型分别保存。非红莉栖模型没有专属情绪脸与漫画符号，程序层通过参数映射驱动眨眼/口型/姿态。
- **舞台摆位**：陪伴舞台里按住角色拖动换位置、滚轮以脚底为锚点缩放；位置与缩放按模型分别记在 `live2d_config`，下次进入恢复。拖动/缩放时模型画布每个方向至少三成留在舞台内（拖不出视野），窗口尺寸变小后越界的摆位自动夹回可见范围。
- Cubism Core 随模型升级到 5.0（`public/live2d/live2dcubismcore.min.js`），以支持 Mao Pro 的 moc3 v5；旧版 moc3（含红莉栖 v4）保持兼容。
- LLM 情绪分类 → 表情枚举 ↔ `.exp3.json` 一一映射，驱动表情与 motion 动作。
- 音频驱动口型同步（TTS 音频幅度 → 口型参数）。
- 待机程序化动画（眨眼、头部微动等）。

### 5.5 飞书渠道

- 与桌面聊天**共享同一对话服务与数据库**，会话标记 `channel=feishu`（修正原版两套互不相通的问题）。
- @提及触发回复；绑定码绑定用户身份；回复走文本模式中文。
- 飞书侧无语音 / Live2D。

### 5.6 视觉输入

- 摄像头开启后前端采集帧（base64 JPEG），服务端每用户保留最近 2 帧。
- 语音对话时作为 image content 块附加到 LLM 请求（pi-ai Message 原生支持 image content）。
- 文本聊天模式不附加。

### 5.7 SQLite 存储

- 单文件数据库，默认 `services/brain/data/amadeus.db`（`DB_PATH` 可覆盖）；brain 启动时自动建库建表，无需安装数据库服务。
- 表：`sessions`（id / user / channel / title / 时间）、`messages`（role / content / `tts_text`（语音回合日文，可空）/ 时间）、`users`（渠道用户绑定，飞书）、`user_configs`（用户级配置，JSON 文本）、`app_state`（键值状态，当前登录用户）。
- **配置单一来源**：以服务端 SQLite 为准（修正原版 localStorage / 数据库 / 进程内 dict 三处重复存储的问题）。
- **登录态单一来源**：桌面端当前登录用户记在 `app_state.current_user_id`；启动时经 `/api/users/current` 恢复，不再写 localStorage。
- v1 无向量检索（Milvus / etcd / MinIO 全部不需要）。

### 5.8 声音（Audio Fish）

- TTS 使用 Audio Fish 预置声音（内含配置好的音色），不做声音克隆。
- v1 先实现为**占位符接口**（返回 mock 音频，保证链路可跑通）；具体接入内容已由需求方编写，待提供后替换落地。

### 5.9 桌宠模式

- 角色以透明、置顶、铺满当前显示器工作区的独立窗口浮在桌面上；进入时主窗口隐藏，退出时恢复。
- 入口：陪伴模式舞台底栏按钮、托盘菜单；托盘提供窗口模式 / 桌宠模式切换与显示 / 隐藏 / 退出。
- 桌宠窗口内也能回到窗口模式：角色右键菜单、对话框底栏按钮。
- 角色可拖动换位置、滚轮缩放；位置与大小记在 `pet_config`，下次进入恢复。
- 待机与戳一戳都是「动作 × 表情」的组合，不是只有动作；害羞只在戳一戳时出现。
- 交互逻辑参考常见的桌宠模式。行为、时序与验证见 [pet-mode.md](pet-mode.md)。

### 5.10 插件中心与数据看板（v1 扩展）

参考常见的「万物皆插件」生态形态：

- **四类插件**：`skill`（SKILL.md 能力包）/ `prompt`（快捷指令模板）/ `theme`（CSS 变量包）/
  `mcp`（stdio MCP 服务）。内置目录 24 条，离线可浏览、搜索、按类型过滤、安装、启停、卸载；
  安装记录落 SQLite `plugins` 表。
- **MCP 运行时**：大脑内置最小 stdio JSON-RPC 客户端（initialize / tools/list / tools/call），
  安装后拉起子进程、列出工具并接入 agent 工具循环；单个服务失败只影响它自己。支持目录预置与自定义命令。
- **快捷指令**：输入框「指令」按钮或 `/` 唤起菜单，模板写入输入框但不自动发送。
- **主题**：应用后写入 `body` 的 CSS 变量，选择在重启后恢复；停用/卸载自动回落默认。
- **数据看板**：`turn_metrics` 记录桌面文本回合的耗时、工具调用与 token（飞书渠道暂未接指标）；
  `/api/stats` 聚合最近 14 天，前端用原生 SVG 图表展示。指标只从本版本开始记录，历史回合不回溯。

详见 [plugins.md](plugins.md)。

### 5.11 记忆、好感度与多模型服务（v1 扩展）

参考常见的角色陪伴与多模型服务设计：

- **长期记忆**：每回合结束后用用户自己的模型提取 0-3 条稳定事实（身份/偏好/事件/关系），
  归一化去重；每回合按「置顶 + 关键词命中 + 新近度」召回并注入 system prompt；记忆页支持
  搜索、新增、编辑、置顶、删除。
- **好感度**：只由真实回合事件累计（基础 +1；认真倾诉、深入交流、一起完成任务各 +1；
  记住一件事 +2），阶段为陌生/认识/熟悉/亲近/喜欢/挚爱；记忆页展示分数、进度、14 天曲线
  与事件列表，文本侧栏同步读数。
- **多模型服务**：`active` 服务优先于内置配置与 `.env`；支持新增/编辑/删除/激活/真实连通性测试；
  密钥只存服务端且不回显；输入框模型选择器写回激活服务；回合指标记录服务名。
- **故障转移**：真实回合失败（连接错误、鉴权失败、空回复）后该服务冷却 10 分钟，期间新回合按
  `priority` 自动改用下一个健康服务；成功一次或测试通过立即解除；设置页显示「故障冷却」徽标。
- **数据真实性**：产品不含任何种子/演示数据；token 来自 pi-ai 的 `usage`，缺失记 0；
  桌面文本、桌面语音与飞书回合都落指标；历史回合不回溯补造。

详见 [memory-and-providers.md](memory-and-providers.md)。

### 5.12 通讯平台接入（v1 扩展）

参考常见的多平台接入：

- **适配器**：Telegram、OneBot v11、Discord、Slack、微信公众号、QQ 官方机器人、通用 Webhook（HTTP 入站/出站）。飞书仍是 `.env` 配置的内置渠道。
- **共用管线**：外部消息 → 绑定/自动建档 → 会话串行队列 → 与桌面相同的 agent 回合、工具、
  记忆提取与好感度 → 指标（`channel = 平台类型`）→ 回复。桌面端能在会话列表看到并继续。
- **身份绑定**：平台内发 `/bind <绑定码>`（绑定码在飞书设置页生成）可把外部账号绑到桌面用户；
  只迁移绑定者自己的私聊。群保持现有 owner（新群首个回合确定），不随说话人或绑定转移，回合记忆/指标同属该 owner。
- **管理界面**：设置 → 通讯平台，支持新增/编辑/删除/启停/真实测试发送、实时状态与错误展示；
  密钥只存服务端且不回显。
- **消息能力**：支持图片、语音、文件附件与平台原生引用回复；绑定后的私聊按身份迁移，群会话保留原 owner。

详见 [platforms.md](platforms.md)。

### 5.13 本地文件转换

- 独立 `/conversion` 页面支持拖放/选择文件、目标格式能力发现、图片批量转 PDF/ZIP、PDF 合并与结果下载。
- 图片、文本、PDF 与 OfficeParser 文档转换在本机 brain 服务内执行；FFmpeg、Poppler、LibreOffice、Tesseract、Pandoc 在存在时接入对应音视频、栅格、Office、OCR 与文档路径。服务只返回当前结果，不把文件写入 SQLite、聊天或外部平台。
- 完整 FlyingMouse 格式矩阵不等于所有组合无损支持；支持情况以 `/api/conversion/capabilities` 与 `/api/conversion/targets` 的运行时结果为准。

详见 [conversion.md](conversion.md)。

### 5.14 知识库（v1 扩展）

- **导入**：粘贴文本 / 上传纯文本文件 / URL 抓取（去标签）。PDF / DOCX 明确拒绝，不把二进制塞进库。
- **检索**：中文 2-gram + 英文词，TF-IDF 打分，返回真实原文片段；不引入 embedding 依赖。
- **使用**：回合开始时把知识库清单注入 system prompt；模型按需调用 `search_knowledge`。
  没有知识库的用户不会看到这个工具。
- **界面**：知识库页支持新建 / 导入 / 文档列表 / 检索预览 / 删除；桌面端与大脑共用同一套数据。
- **限制**：不支持同义改写召回、增量索引、OCR、跨用户共享。

详见 [knowledge.md](knowledge.md)。

### 5.15 自动化任务（v1 扩展）

- **调度**：间隔（5 分钟 ~ 7 天）/ 每天固定时刻 / 一次性；服务端每 15 秒检查到期任务。
- **执行**：到点跑真实 agent 回合（同一套人格、工具、记忆、知识与指标），结果落 `automation-<id>` 独立会话。
- **可靠**：数据库 `running` 状态防重入；大脑重启清理被中断的任务；单任务失败不影响其它任务。
- **界面**：任务页支持新建 / 编辑 / 启停 / 立即运行 / 展开真实结果 / 打开运行会话。
- **事件触发**：支持文件变化与 Webhook 事件触发；任务依赖编排仍不在本轮范围。

详见 [automations.md](automations.md)。

### 5.16 工作台增强（v1 扩展）

- **会话置顶**：置顶单独成组，置顶不刷新 `updated_at`。
- **正文搜索**：侧栏标题过滤 + 服务端全文 LIKE 搜索（带命中片段）。
- **编辑后重发**：不修改原消息；以原消息的 `parent_id` 为分叉点创建新用户消息和回复，旧分支保留并可切换。
- **用量**：标题栏显示会话级真实 token 累计（来自 `turn_metrics`）。
- **工件预览**：助手输出里的 HTML / SVG / Mermaid 在右侧沙箱渲染；Mermaid 动态加载。
- **附件 / 图片输入**：已支持落盘、文本抽取、语音转写与视觉模型门控，详见 [attachments-branches.md](attachments-branches.md)。
- **消息树**：`messages.parent_id` + `sessions.active_leaf_id`，当前路径与隐藏分支分别读取。

详见 [agent-assistant.md](agent-assistant.md)。

### 5.17 Agent 工作台 GUI（v1 扩展）

参考常见的并行 agent 工作区，把文本模式升级为「会话 + 运行图 + 终端 + 工件」工作台：

- **布局**：顶部模型服务条、会话标题栏、阶段管线；中间消息列 + 输入区；右侧运行图 / 终端 / 工件三页签；底部状态条。
- **运行图**：每个会话一条泳道，节点来自真实消息；当前会话逐条绘制，其它会话按服务端消息数绘制；点击泳道切换会话。
- **阶段管线**：思考 → 工具 → 回复 → 完成，只由真实流式事件推进。
- **流动光线**：流式气泡的 SVG 流动边框、活动泳道的流光与节点脉冲；尊重 reduced-motion。
- **终端**：当前会话真实工具调用（命令、参数、结果、状态），暗色 mono 呈现。
- **工件**：从助手代码块提取 HTML / SVG / Mermaid，复用沙箱预览。
- **视觉**：白/浅灰画布、hairline 边框、低饱和蓝灰主色与多色分支；仅作用于工作台，不改其它页面。
- **限制**：运行图只画并行会话，不画消息分支树（消息分支在聊天里切换）；没有 diff 数据，因此不提供差异页签；终端只显示本进程记录到的工具活动。

详见 [workbench.md](workbench.md)。

### 5.18 消息附件与分支树（v1 扩展）

- **附件**：输入区可选择/拖拽/粘贴图片、语音、文件；服务端落盘到 `data/media`，消息只带元数据与 `/api/media/<id>`。
- **模型输入**：文本文件抽取正文、语音走 Whisper 转写；图片按模型视觉能力门控；文本附件进入后续回合上下文。
- **分支树**：`messages.parent_id` + `sessions.active_leaf_id`；编辑与重新生成创建兄弟分支，旧分支保留，消息 meta 可 `‹ 1/2 ›` 切换。
- **限制**：不做跨会话合并；历史图片不重复送入模型；`messageCount` 统计整棵树。

### 5.19 自动化事件触发（v1 扩展）

### 5.20 模型路由组与配额（v1 扩展）

- **路由组**：服务可打 `chat / vision / summary / memory` 标签；文本回合走 chat，带图片走 vision。
- **每日配额**：`dailyTokenQuota` > 0 时按 `turn_metrics.provider_id` 汇总当天真实 token；超限服务自动跳过。
- **展示**：服务卡片显示标签、今日用量与配额状态；指标记录 provider id。

### 5.21 主动问候（v1 扩展）

- **后台视觉路径**：应用处于后台或桌宠模式时，由桌面主进程每 10~15 分钟随机截取当前显示器，交给视觉模型生成 1~2 句问候；前台、忙碌回合不触发，截图不落库。
- **空闲路径**：空闲 ≥ N 分钟、处于时间窗、今日次数未超限、距上次问候足够久；brain 每 60 秒检查一次。
- **生成**：空闲路径使用真实模型 + 记忆召回 + 好感度阶段，写入用户最近活跃的未归档桌面会话（不按置顶排序）；没有用户消息的账号不问候。视觉路径只追加助手消息，不伪造用户输入。
- **界面**：通用设置提供后台视觉问候开关；设置 → 陪伴配置提供空闲问候的开关、时间窗、每日上限；陪伴页轮询自动显示空闲问候，视觉问候通过桌面 IPC 推送。
- **限制**：不做主动语音播报、剧情模式与多轮主动追问。

详见 [proactive.md](proactive.md)。

### 5.22 效率与工作区（v1 扩展）

- **命令面板**：⌘/Ctrl+K 一处搜动作、页面、会话与消息正文；空查询显示动作与最近会话。
- **只读工作区**：右侧面板「文件」页读取真实文件树与 Git 变更，文件正文与 diff 在弹窗里看；
  路径越界被拒绝，`.env` / 私钥 / 内部状态目录不进入文件树，直接正文与 diff 接口同样拒绝读取。
- **输入区**：`@` 引用工作区文件（只插入路径文本，不读文件内容）；`/` 打开内置命令
  （新建 / 分支树 / 导出 / 主题 / 各页面）与插件快捷指令；生成中发送进入排队，回合结束后自动发出。
- **上下文读数**：按可见消息正文估算 token / 模型窗口，明确标注是估算。
- **分支树弹窗**：列出全部保留分支，标出当前活跃路径，点旧分支切回继续。
- **导出**：会话导出为 Markdown（内容取自落库消息，不补写）。
- **完成通知**：窗口不在前台时回合完成发系统通知（需用户开启并授权）。

### 5.23 回合改动卡与会话归档（v1 扩展）

- **改动卡**：桌面端回合在开始与结束时各取一次 `git status` 快照，差集写入该条助手消息；
  卡片列出本回合真实改动的文件，点文件名在右侧工作区面板打开未提交 diff。非 Git 目录或未开启工具时不产生卡片。
- **会话归档**：归档不删除、不刷新 `updated_at`；默认列表隐藏，侧栏「已归档」分区可展开与恢复。
- **快捷键速查**：⌘/Ctrl+/ 或命令面板打开，列出所有已实现的键位。

### 5.24 联网搜索与网页读取（v1 扩展）

参考常见 agent 的网页能力组合：

- **两个工具**：`search`（返回标题 / 链接 / 摘要，支持条数与时效过滤）与 `fetch_url`
  （打开网页，HTML 转纯文本）；搜索看摘要、需要细节时再读原文。
- **多引擎降级**：Tavily（配了密钥才有）→ 必应 → 360 → 搜狗 → DuckDuckGo，
  单引擎最多 8 秒、整条链共用 20 秒；空结果继续换下一个；区分真实零命中与网络/解析/人工验证故障，
  全部失败产生工具错误并保留各引擎原因。DuckDuckGo 使用网页结果而非 Instant Answer。
  时效过滤只走支持该条件的引擎（Tavily / Bing / DuckDuckGo），不以不限时间结果冒充。
- **结果清洗**：过滤「其他人还搜了 / 大家还在搜」推荐词块与搜索引擎站内链接，按 URL 去重；
  先过滤再按条数截断（反过来会在杂质排在前面时返回空结果）。
- **抓取边界**：仅公网 http(s)；本机与内网网段拒绝；二进制/媒体不解析；正文有上限并标注截断；
  用户停止回合时请求一并取消。
- **界面**：设置 → 联网搜索，显示每个引擎在此刻网络下的真实可达性（并发探测、不缓存），
  并提供真实试搜；诊断接口 `/api/search/status|test|fetch` 与聊天工具共用实际网络代理和解析器；
  试搜结果标明查询词，进行中不会被 Enter 重入或旧响应覆盖。
- **限制**：免密钥引擎是 HTML 解析，站点改版会让该引擎失效（状态页立刻可见，其余引擎继续）；
  不做反爬对抗与登录态抓取。

详见 [web-search.md](web-search.md)。

## 6. 跨端契约（从原版保留）

- SSE 事件词汇：`delta` / `done` / `error`（`delta` 内容永远只有中文）；语音模式另需 `transcript` / `emotion_response` 等（细节实现时定）。
- 用户配置模型（原 `InputData`）：LLM 端点 / 密钥 / 模型、输出语言、system prompt 等 → 迁移为**共享类型包**（修正原版无共享类型的问题）。
- 双语言流式标识符约定：v1 新增，**仅大脑服务内部**（LLM 流解析 + TTS 切句）使用，前端与存储无感知。
